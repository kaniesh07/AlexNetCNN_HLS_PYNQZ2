# Architecture: AlexNet-C10 on the PYNQ-Z2 (Vitis HLS)

## Goals → design decisions
| Goal | What the design does |
|---|---|
| **Minimum latency** | The whole network is on chip. 361,568 int8 weights sit in BRAM ROMs inside the HLS IP, and both activation maps sit in BRAM, so there are no DDR round trips. One pipelined loop per layer runs at II = 1 with **256 MACs/clock**. Pooling, ReLU and requantisation are fused into the same loop, so there is no extra pass. fc6 is turned into a 4×4 convolution, so it needs no separate flatten step. Argmax runs in hardware, and results come back over AXI-Lite, so there is no output DMA. |
| **Minimum power / energy** | The only external traffic is the 4 KB image. Two MACs are packed per DSP48E1 (`mac2()`): 128 DSPs instead of 256. The requantiser's input is clamped to 24 bits, so it needs 1 DSP per lane instead of 2; this is proven exact for the trained model. `config_rtl -reset control` keeps reset fan-out small, Vivado `power_opt_design` gates BRAM and register clocks, and the short run time means less static energy per image. |
| **Maximum accuracy** | The network width is the largest that keeps every weight on chip. Training is BatchNorm + augmentation + label smoothing, followed by quantisation-aware fine-tuning in the exact hardware formats. Activations are unsigned 8-bit (one bit more resolution than signed int8), and weights use per-channel scales. Result: **88.99% on the full CIFAR-10 test set**, bit-exact with the hardware. |

## Network (AlexNet topology scaled to 32×32)
| Layer | Op | In → out | MAC steps (clocks) |
|---|---|---|---|
| conv1 | 3×3 p1 + ReLU + max-pool 2 | 3×32×32 → 32×16×16 | 9,216 |
| conv2 | 3×3 p1 + ReLU + max-pool 2 | → 64×8×8 | 18,432 |
| conv3 | 3×3 p1 + ReLU | → 96×8×8 | 13,824 |
| conv4 | 3×3 p1 + ReLU | → 96×8×8 | 20,736 |
| conv5 | 3×3 p1 + ReLU + max-pool 2 | → 64×4×4 | 13,824 |
| fc6 | FC 1024→128 + ReLU (run as 4×4 conv) | → 128 | 512 |
| fc7 | FC 128→128 + ReLU | → 128 | 64 |
| fc8 | FC 128→10, raw int32 → argmax | → 10 | 16 |
| **total** | | | **76,624** |

## Kernel (`hls/src/cifar_accel.cpp`)
```
img (AXIS, 1024 beats) -> ibuf (BRAM)
for layer 0..7:  run_layer()   one instance, II = 1, 256 MAC/clk
    read  : ibuf (layer 0) or act[src][cg%4]  (zero padding by bounds check)
            WROM[wptr][0..31]                 (32 BRAM ROM banks x 64 bit)
    MAC   : 16 lane pairs x 8 inputs, mac2() = 2 MACs / DSP48E1
    on the last step of an output pixel:
            + bias, requant (24b x 16b, 1 DSP/lane), ReLU (clamp), 2x2 max
            write 4 x 64-bit words (one per bank) to act[dst]
argmax -> ap_return ; logits[10] -> s_axilite
```
* The loop nest, flattened into one pipelined loop, is: tile (32 out ch) > py > px > pool sub-pixel > cg (8 in ch) > ky > kx.
* Activation layout: channel group `cg` is stored in bank `cg % 4` at address `((cg/4) << 2·lgW) | (y << lgW) | x`. Each output pixel's 32 channels go to 4 banks in one clock.

## Interface (all offsets are generated by HLS → `xcifar_accel_hw.h`)
| Port | Type | Content |
|---|---|---|
| `img` | AXI4-Stream slave, 32 bit | 1,024 beats `{0,B,G,R}`, TLAST on beat 1023 |
| `s_axi_control` | AXI4-Lite | ap_ctrl_hs, `ap_return` = class (or −1 = bad frame), `logits[10]` array |
| `interrupt` | level | ap_done (wired through `axi_intc` for PYNQ) |

## Block design
PS7 GP0 → SmartConnect → {cifar_accel s_axi_control, AXI DMA lite, AXI INTC}. DMA MM2S (HP0) → `cifar_accel/img`. One clock (FCLK0 = 150 MHz target) and one reset domain.
